# artifact-ux — Claude artifact constraints & Definition of Done

The claude.ai artifact iframe has hard constraints that break common web patterns. This skill
encodes them so every artifact ships correctly — and highlights the medium's unique strengths.

---

## Hard technical constraints (non-negotiable)

| Constraint | Rule |
|---|---|
| **No external API calls** | The artifact is sandboxed. All data must be inline or generated by JS itself — no fetch/XHR at runtime. |
| **No persistence** | No `localStorage`, `sessionStorage`, `IndexedDB`, or cookies. Every session starts fresh — design for it. |
| **No external fonts** | No Google Fonts CDN calls. Use `system-ui` or embed as base64 data URIs if custom typography is required. |
| **No multi-route apps** | Single-page model only. Navigation inside the artifact is state-based JS, not URL routing. |
| **No ES module CDN imports** | Avoid external CDN imports unless the artifact is explicitly React-mode — even then, test sandbox accessibility. |
| **Width range** | Design for 360px minimum, 800px comfortable maximum. |

---

## Interaction constraints

**No hover-only affordances.**
A meaningful share of claude.ai users are on mobile. Any interaction that requires hover to discover or activate fails the artifact. Every feature must be accessible by tap.

**Touch targets: minimum 44×44px** for every interactive element — buttons, icons, controls, close targets. No exceptions.

**Scroll conflict warning.**
The artifact renders in an iframe. Scroll inside the iframe can conflict with the parent page scroll. Avoid requiring precise scroll position for key interactions — put primary actions in the visible viewport zone without scrolling.

**Keyboard navigation must work.**
Tab order must be logical (left-to-right, top-to-bottom). Enter/Space must activate buttons. The iframe sandbox isolates focus — test Tab navigation from the first element through to the last.

---

## Design opportunities specific to the medium

**Self-contained = portable.**
The entire artifact runs without a server — it can be shared as a URL. Design to this strength: make the artifact feel complete and self-sufficient. No "connect your data" onboarding.

**Instant render.**
No loading state needed for initial content if data is inline. Use this. Show the fully populated end state immediately on load — never start blank or with skeletons.

**Demo-first by nature.**
Artifacts are primarily shared to communicate and demonstrate, not for daily operational use. Apply demo mode design rules from `story-audit` by default: lead with the interesting state, not the setup wizard.

---

## Definition of Done — Claude artifacts (all 10 required before shipping)

1. Renders correctly at **400px width** and at **720px width**
2. All interactive elements work **without hover** (test by removing cursor / testing on mobile)
3. **Keyboard navigation** works: Tab moves through all interactive elements, Enter/Space activates buttons
4. **No blank opening state** — content is visible immediately on load
5. No **external font or icon CDN calls** (check Network tab or audit src/href attributes)
6. No **localStorage or sessionStorage** references anywhere in the code
7. Works in **dark mode** — reads correctly on both Claude.ai light and dark themes
8. All text meets **AA contrast** (4.5:1 for normal text, 3:1 for large text)
9. A cold viewer can **state the artifact's purpose in 10 seconds** (cold-read test — see story-audit)
10. **Primary CTA or key interaction is visible without scrolling** on a 400px-wide viewport

## Aesthetic guidance

Apply `design-taste` bans (no gradients-as-backgrounds, no card-shadow stacking, no decorative dividers) plus:

- **Agnostic/client work:** use `modern-tech-editorial` tokens
- **DS-branded work:** use `ds-design-system` tokens

**Token layer via inline `<style>`.** Use CSS custom properties in a `<style>` block at the top of the artifact. Do not rely on external CSS files — they will not load in the sandbox.

**Avoid Inter at default weight.** It renders poorly at small sizes in the iframe context. Use `system-ui` with `font-weight: 450–500` if custom type is unavailable.

Example minimal token block for a clean agnostic artifact:
```css
:root {
  --bg: #16181c;
  --surface: #1e2025;
  --text: #f0f0f0;
  --text-muted: #888;
  --accent: #00d4ff;
  --radius: 6px;
  --font: system-ui, -apple-system, sans-serif;
}
```

## What to encode vs. leave to human judgment

**Encoded here (this skill owns):**
- Hard sandbox constraints — fixed by the platform, never negotiate them
- Interaction constraints — mobile-first, 44px targets, scroll warning, keyboard nav
- The 10-item Definition of Done — apply every time, no exceptions
- Demo-mode-by-default rule — always show populated state on load

**Left to human judgment:**
- Visual aesthetic — handled by `modern-tech-editorial` or `ds-design-system`
- Whether to use inline data vs. generate synthetic data for the demo state
- Complexity of the interaction model for this artifact's specific purpose
